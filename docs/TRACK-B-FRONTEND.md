# Track B: the match client

Your half of the split. Everything here lives in `src/app/**/page.tsx`, `src/components/`, and the client-side helpers under `src/lib/`. You will not touch a route handler, a migration, or the Python worker, so your branch and the backend branch should merge without conflicts.

## The milestone

Two browsers queue for a Medium match, get paired, see a real problem loaded from the database, type Python, submit, and watch a real result come back from the judge.

The pages for all of this exist and none of them work. `src/app/match/round/page.tsx` is a convincing mockup with a hardcoded problem, a countdown starting from a literal `600`, and a `setTimeout(1800)` that pretends the opponent submitted. Your job is to replace the pretending with real state.

Out of scope: practice mode, placements, chat, reports, rematch, profiles, leaderboard. Leave those pages as they are.

## The problem you have to solve first

The routes you need do not exist yet. The backend track is building them in parallel, and if you wait for them you have lost a week.

So step B1 builds a mock that satisfies the contract exactly, behind an environment flag. You develop the entire match flow against a fake match that advances on a timer. When the real routes land you flip one variable and the same code hits Postgres. This is the whole reason the split works, so do B1 before anything else even though it feels like a detour.

## The contract

`src/types/api.ts` is on `main`. It is the exact JSON the backend will return, and your mock must satisfy it or you will build against a fiction.

Import types from it everywhere. Never redeclare a response shape locally, because a local duplicate is how the two halves drift apart without either of us noticing until merge day.

Treat the file as frozen. If you need a field that is not there, message your friend and change it in its own commit on `main` that you both rebase onto.

## Decide the URLs now

The lobby currently receives `?matchId=X&level=medium` from the queue page. Lock the rest of the scheme before you write routing code:

```
/queue                                        (exists, already wired)
/match/lobby?matchId=<uuid>
/match/round?matchId=<uuid>&roundId=<uuid>
/match/results?matchId=<uuid>&roundId=<uuid>
/match/complete?matchId=<uuid>
```

Drop `level` from the query string. It is in `MatchState.difficulty` and a URL parameter the server does not verify is a thing that will eventually disagree with the database.

## Step B1: the API client and the mock

Create `src/lib/api-client.ts`. Every page calls these functions and no page calls `fetch` directly, so there is exactly one place to flip when the real routes arrive.

```ts
import type {
  ApiError, DraftState, MatchState, ReadyResult, RoundState, SubmitResult,
} from "@/types/api";

export class ApiRequestError extends Error {
  constructor(readonly status: number, message: string) {
    super(message);
  }
}

async function request<T>(path: string, init?: RequestInit): Promise<T> {
  const response = await fetch(path, { cache: "no-store", ...init });
  if (!response.ok) {
    const body = (await response.json().catch(() => null)) as ApiError | null;
    throw new ApiRequestError(response.status, body?.error ?? "Request failed.");
  }
  if (response.status === 204) return undefined as T;
  return (await response.json()) as T;
}

const json = (body: unknown): RequestInit => ({
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(body),
});

export type MatchApi = {
  getMatch(matchId: string): Promise<MatchState>;
  getRound(roundId: string): Promise<RoundState>;
  getDraft(roundId: string): Promise<DraftState>;
  saveDraft(roundId: string, sourceCode: string): Promise<void>;
  submit(roundId: string, sourceCode: string): Promise<SubmitResult>;
  ready(matchId: string): Promise<ReadyResult>;
  surrender(matchId: string): Promise<void>;
};

const liveApi: MatchApi = {
  getMatch: (matchId) => request(`/api/matches/${matchId}`),
  getRound: (roundId) => request(`/api/match-rounds/${roundId}`),
  getDraft: (roundId) => request(`/api/match-rounds/${roundId}/draft`),
  saveDraft: (roundId, sourceCode) =>
    request(`/api/match-rounds/${roundId}/draft`, {
      method: "PUT",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ sourceCode }),
    }),
  submit: (roundId, sourceCode) =>
    request(`/api/match-rounds/${roundId}/submissions`, json({ sourceCode })),
  ready: (matchId) => request(`/api/matches/${matchId}/ready`, json({})),
  surrender: (matchId) => request(`/api/matches/${matchId}/surrender`, json({})),
};

export const api: MatchApi =
  process.env.NEXT_PUBLIC_MOCK_API === "1"
    ? // eslint-disable-next-line @typescript-eslint/no-require-imports
      (require("@/lib/mock-api").mockApi as MatchApi)
    : liveApi;
```

Note `saveDraft` uses `PUT`. The existing route only accepts `PUT`, and `src/proxy.ts` rejects any mutation whose `Origin` header does not match, which same-origin fetch handles for you.

Then `src/lib/mock-api.ts`. Make it a real state machine on a clock rather than static fixtures, because a fake that never changes will not exercise the transitions you actually have to get right.

Have it hold one in-memory match and advance on wall-clock time from first access:

- 0 to 5 seconds: match `waiting`, lobby countdown.
- 5 seconds: round 1 goes `active` with `endsAt` 90 seconds out, so you are not waiting ten minutes to test expiry.
- 8 seconds after you submit: opponent submits, then `revealed` becomes true with a scripted result.
- Round 2 and 3 follow the same shape, with round 2 as a loss and round 3 as a win, so you see every branch.

Give it three problems with real statements, real starter code, and two public tests each. Set `serverTime` on every response to `new Date().toISOString()` shifted by a deliberate 40 seconds, so you actually notice if a component reads the local clock instead of the corrected one.

### Verify

Nothing to look at yet. `bunx tsc --noEmit` should pass and `mockApi` should satisfy `MatchApi` without casts.

## Step B2: hooks for polling and time

There are no WebSockets in this project. `docs/BACKEND.md` describes a WebSocket match update, but nothing implements one, and a custom server for Next 16 is a bigger piece of work than this milestone deserves. Poll for now, and keep every poll behind these hooks so swapping in SSE later is a change to two files.

Create `src/lib/hooks/use-server-clock.ts`:

```ts
"use client";

import { useCallback, useRef } from "react";

/**
 * Corrects for clock skew between the browser and the server.
 *
 * The round timer must never be driven by Date.now() alone. A player whose system
 * clock runs slow would get extra seconds, and the server would auto-submit their
 * code while the UI still showed time remaining.
 */
export function useServerClock() {
  const offset = useRef(0);

  const sync = useCallback((serverTime: string) => {
    offset.current = Date.parse(serverTime) - Date.now();
  }, []);

  const secondsUntil = useCallback((iso: string | null) => {
    if (!iso) return null;
    return Math.max(0, Math.round((Date.parse(iso) - (Date.now() + offset.current)) / 1000));
  }, []);

  return { sync, secondsUntil };
}
```

Then `src/lib/hooks/use-match.ts` with `useMatchState(matchId)` and `useRoundState(roundId)`. Both should poll every 2000ms, call `sync(state.serverTime)` on each response, expose `{ data, error, refresh }`, and stop polling when the thing they are watching reaches a terminal state. A completed match does not need to be asked about forever.

Two details worth getting right. Skip a poll while the previous one is in flight, or a slow response turns into a pile-up. And keep a separate 1-second `setInterval` purely to re-render the countdown, so the displayed clock ticks smoothly between polls instead of jumping every 2 seconds.

## Step B4: the lobby

Rewrite `src/app/match/lobby/page.tsx`.

Read `matchId` from `useSearchParams`. Poll with `useMatchState`. Show the opponent's handle and rank from `state.opponent`, the difficulty, and a countdown from `lobbyEndsAt` through `secondsUntil`.

Handle the case where the match is already `active` when the page loads, because that is what a refresh looks like. Redirect straight to the round.

## Step B5: the round page

The big one. Rewrite `src/app/match/round/page.tsx` completely.

Read `matchId` and `roundId` from the URL. Poll `useRoundState(roundId)`.

**Render the real problem.** `state.problem` gives you `title`, `statementMarkdown`, `starterCode`, and `publicTests`. For the examples, render `inputData` and `expectedOutput` from `publicTests` instead of the hardcoded block that is there now.

`statementMarkdown` is markdown. Rather than adding a dependency to the shared `package.json`, write a small renderer in `src/components/markdown.tsx` that handles the subset the seed problems use: paragraphs, `##` headings, fenced code, inline backticks, and bullet lists. About forty lines. If you decide you want `react-markdown` after all, tell your friend before touching `package.json`.

**Fix the escaped newline bug while you are here.** The current `<pre>` block contains `\n` inside JSX text, which renders as a literal backslash and an n rather than a line break. The same bug is in `src/app/practice/page.tsx`. Use a template literal or real newlines in the string.

**Drive the timer from the server.** Replace `useState(600)` with `secondsUntil(state.endsAt)`. Never count down from a constant.

**Restore and autosave the draft.** On mount, `api.getDraft(roundId)`, and fall back to `problem.starterCode` when `sourceCode` is null. Then debounce `api.saveDraft` at roughly 3 seconds after typing stops. This matters more than it looks: when the timer expires the worker auto-submits the player's last saved draft, so an unsaved buffer means their work is thrown away and the starter code gets judged instead.

**Submit locks the round.** `api.submit(roundId, code)` returns 202 and the round is locked for that player. Disable the editor. A second submit returns 409 with "Your solution is already locked", so handle that rather than showing a raw error.

**Wait for the reveal.** After submitting, keep polling. `youSubmitted` and `opponentSubmitted` drive the status text. Only when `revealed` is true does `result` arrive. Then move to `/match/results`.

The reveal rule is deliberate and worth preserving exactly: results stay hidden until both players have submitted and both judge jobs finish. Showing a partial result early turns the match into a live scoreboard and changes how people play it.

**Handle expiry.** When the countdown hits zero and the player has not submitted, the worker auto-submits their draft. Do not submit from the client on expiry, because you will race the worker and get a 409. Show "Time expired, your saved draft was submitted" and keep polling.

## Step B6: results and complete

`src/app/match/results/page.tsx` reads `result` from the round: `outcome`, `yourTestsPassed`, `opponentTestsPassed`, `testsTotal`, and both verdicts. Render verdicts in plain language. `wrong_answer` should read as "Wrong answer", `time_limit_exceeded` as "Time limit exceeded".

Then poll the match. If `activeRound` is non-null, there is another round, so offer ready-up and route back to `/match/round`. If `status` is `completed`, route to `/match/complete`.

`src/app/match/complete/page.tsx` shows `outcome`, the round tally from `roundsWonByYou` and `roundsWonByOpponent`, and the opponent's handle.

Do not show any rating number. `docs/PRODUCT.md` is explicit that MMR stays server-only and progression is shown through wins, promotion status, and rank emblems. The backend will not send you an MMR to display anyway.

Leave the rematch and report buttons as dead links for this milestone.

## Step B7: integration

Once your friend's branch is merged to `main`:

```bash
git checkout main && git pull
git checkout track-b-frontend && git rebase main
```

Set `NEXT_PUBLIC_MOCK_API=0` in `.env.local` and add:

```
DATABASE_URL=postgresql://codewars:codewars_local_only@localhost:5432/codewars
```

Then:

```bash
docker compose -f docker-compose.local.yml up -d db
docker compose -f docker-compose.local.yml up --build judge-worker
bun dev
```

Run the full flow in two browser profiles, not two tabs. Two tabs share a session cookie and you will get matched against yourself, which the database rejects.

Checklist:

- [ ] Both players sign in via the dev login your friend added and reach `/queue`.
- [ ] Both queue for Medium. The second one gets a match.
- [ ] Both land in the lobby and see each other's real handle and rank.
- [ ] Ready-up starts round 1 for both within one poll interval.
- [ ] Both see the same problem, loaded from Postgres, with two worked examples.
- [ ] Typing, then refreshing the page, restores the draft.
- [ ] Player A submits a correct solution. Player B still sees "Working".
- [ ] Player B submits a wrong one. Both see the result within a few seconds.
- [ ] Tests-passed counts match what the judge actually recorded.
- [ ] Rounds 2 and 3 run. The match completes with the right winner.
- [ ] Let one round's timer run out with unsaved edits, and confirm the saved draft was judged rather than the starter code.
- [ ] No MMR number appears anywhere in the UI or in any network response.

`bun run lint` and `bunx tsc --noEmit` should both be clean before you push.
